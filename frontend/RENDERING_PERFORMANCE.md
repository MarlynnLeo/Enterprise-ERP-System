# 主题与图表渲染约定

所有桌面主题共用菜单交互、性能策略和图表入口。主题只负责视觉差异，不应改变菜单展开或路由切换的工作量。

## 性能状态与生命周期

- `main.js` 在应用挂载前初始化 `utils/performanceMode.js`，卸载时释放监听器。读取快照不启动监听器。
- `getPerformanceMode()` 返回不可修改的 `{ lowEnd, reducedMotion, saveData }` 快照；CSS class 与快照来自同一次刷新。业务模块不要直接读写独立的全局性能变量。
- 减少动态效果、慢速显示设备、省流及跨标签页的手动低配偏好变化，统一由运行时更新。重复初始化不重复挂监听，也不重写未变化的 class。
- 低配检测只读 CPU/内存元数据、浏览器偏好和已有的 `erp_low_end_mode` 设置。禁止为了探测硬件而创建 Canvas/WebGL 上下文；初始化图形驱动本身可能阻塞部分 Windows 电脑。
- 元数据不能准确表示显卡性能。普通模式也必须避免无用途的大面积持续重绘，不能只依赖自动低配识别。
- 主题预取属于可选工作，只在运行时允许时排入空闲队列，同一主题去重，实际执行前再检查策略。显式选择主题仍正常加载所需 CSS；应用销毁后不再预取。

## 样式职责

- `assets/performance-policy.css` 是动画时长、延迟、循环次数和低配装饰效果的统一入口。根节点、元素和两种伪元素使用同一约定。
- 主题和组件声明正常动效时不使用 `!important`。公共策略保留对性能长属性的优先权；菜单等明确禁止动画的功能性 `none` 规则可以保留。
- 不依赖 CSS cascade layer 或现代选择器才能降级。减少动态效果的媒体查询也覆盖应用初始化前的样式。
- 使用极短的非零时长保留弹层所需的动画/过渡结束事件，不通过取消事件或强制移除 DOM 达成降级。
- 低配阴影和毛玻璃在公共入口处理，阴影 token 必须压过后加载的主题色板。表单的 inset 边框、聚焦提示和可读性不能被全局阴影重置误删。
- 大面积常驻容器不做持续装饰动画。布局隔离不能改变全屏弹层或 fixed 元素的包含块。

## 图表职责

- ECharts 仅从 `utils/echartsCore.js` 导入，Chart.js 仅从 `utils/chartCore.js` 导入；页面不要绕过这些入口直接导入图表包。
- ERP 统计图表在所有模式下直接呈现数据，初次、更新、状态切换及图形离场不运行装饰动画。提示、图例选择、缩放和业务回调保持可用。
- 统一规则由 ECharts 公开的 preprocessor 和 Chart.js 生命周期插件实现。不要替换实例方法、改写库内部 painter 字段或加入仅为控制动画的伪组件。
- `utils/chartPerformance.js` 只遍历动画配置节点，不扫描业务数据数组。后续合并或替换选项也不能重新打开装饰动画。
- 低配/省流模式创建画布时，DPR 不超过 1；普通模式和仅减少动态效果时保留正常清晰度。已创建的画布保留其分辨率，后续模式变化作用于新画布，避免重建丢失图例、缩放或选择状态。
- Chart.js 的主题监听随真实实例销毁释放；ECharts 页面继续负责其业务图表的 resize 与 dispose 生命周期。

## 主题状态与验证

主题 store 按实际 DOM 同步其拥有的 class、data-theme 和 CSS 声明。相同设置重放不得触发多余根属性写入；预设恢复按声明存在性处理，包括空白值与 `!important`。读取语义背景色后，再批量写入派生字色。

提交前运行 `npm run check:performance`、`npm test` 和 `npm run build`。策略回归检查应覆盖真实图表库的运行状态及 CSS 规则的优先级约定，不能只检查某段源码是否存在。

浏览器验收使用生产构建及隔离数据，检查全部主题、后加载色板、hover、弹层结束事件、默认头像、高 DPR、低配及系统减少动态效果。菜单检查包含第一次展开、重复展开、键盘导航、首次进入页面和移动端抽屉。CPU 限速/禁 GPU 的本地结果只作为模拟证据；故障电脑是否恢复仍以更新后的现场验收为准。
